# Разбор: коммиты 27c4c57 и 7710304 (проверка SD-GEN)

> Связанный issue: [#1](https://github.com/srg888/paytracker/issues/1).
> В тексте issue есть опечатка («Коммит `verifying`» вместо `27c4c57`) — редактирование
> issue недоступно текущему токену, поэтому исправление зафиксировано здесь.

## Суть

При переносе легаси-реестра проверка пометки «номер сгенерирован при переносе»
сверялась с префиксом `SD-GEN-`:

```python
if row['sd_number'].startswith('SD-GEN-')
```

Коммит `27c4c57` заменил `SD-GEN-` на `SD?-строка`, заявив, что в коде была опечатка.
Коммит `7710304` вернул `SD-GEN-` обратно. Итог: два коммита взаимно сократились,
`7710304` эквивалентен `dfa18e4` по этой строке.

## Почему путаница

В скрипте **до** `dfa18e4` была строка `sd_number = _clean(row["№ SD"]) or f"SD?-строка{row_num}"` —
запасной идентификатор для строк без номера. При подготовке данных номера `SD-GEN-1…14`
были проставлены в самом CSV (14 строк шли без «№ SD»), поэтому проверка на `SD-GEN-`
была согласована с данными.

## Подтверждение по прод-данным

```
[Перенесено из Excel-реестра, № SD: SD-GEN-3 (номер сгенерирован при переносе —
в исходном реестре его не было); статус в реестре: Исполнено] Нержавейка
```

Пометка присутствует у всех 14 строк в `requests.description`.

## Выводы на будущее

1. Сверяться с прод-данными, а не только с кодом — `description` в БД является первоисточником.
2. Не «исправлять» согласованное: если код и данные совпадают, правка ради соответствия
   комментарию в другом файле создаёт риск рассинхронизации.
3. Перед пушем воспроизводить заявленный баг: для `27c4c57` достаточно было посмотреть
   `description` в БД или `git log -p dfa18e4`.
4. Проверять итоговый diff: `git diff dfa18e4..HEAD` показал отсутствие изменений по этой строке.
